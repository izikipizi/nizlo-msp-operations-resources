# Contributing

Corrections and practical additions are welcome through GitHub issues and pull requests.

Useful contributions include:

- correcting an operational step, field definition, formula, or accessibility issue;
- replacing a broken or outdated source with a current primary source;
- improving a checklist or CSV schema without weakening its evidence or approval boundaries;
- proposing a new vendor-neutral MSP or IT-operations checklist, worksheet, or dataset; and
- reporting a broken local link, canonical URL, sitemap entry, feed entry, or machine-readable record.

## Contribution expectations

- Keep each pull request focused on one resource or one closely related repair.
- Explain the operational problem, the proposed change, and how you validated it.
- Prefer current primary sources from vendors, standards bodies, or public agencies.
- Preserve authorization, evidence, rollback, exception ownership, and validation boundaries where they apply.
- Do not include customer data, secrets, personal information, fabricated evidence, fake reviews, affiliate links, paid-placement language, or unsupported product claims.
- Disclose any employment, vendor, product, or commercial relationship relevant to the change.
- Run `git diff --check` and verify all changed local links before opening the pull request.

For data or template changes, include the affected row count, field count, identifier rules, and any schema or checksum updates. For a new public page, update the library index, sitemap, feed, `llms.txt`, structured resource indexes, and other machine-readable surfaces that describe the catalog.

Maintainers may request narrower wording, stronger sources, additional validation, or a different placement. Inclusion does not imply that Nizlo or any referenced vendor endorses a contribution.
