An installed agent is not an accepted endpoint.

Use these five evidence gates before expanding an RMM pilot. Each gate defines a success criterion, the proof to retain, and a stop condition that blocks a wider rollout.

1. Identity and placement

Prove one current, stable endpoint record under the intended tenant, customer, and site. Stop for duplicates, stale check-ins, or ambiguous identity.

2. Controlled detection

Create a harmless known condition and retain the alert, timestamps, device context, severity, and owned route. Stop if it is missing, late, or misrouted.

3. Authorized action

Run one low-risk approved action and retain who targeted what, when it ran, its output, and its final state. Stop on the wrong target, privilege, or unknown result.

4. Patch reconciliation

Reconcile the baseline scan, attempted change, reboot state, post-action scan, and any exception. A dispatched job alone is not completion evidence.

5. Removal and handoff

Prove that access, tokens, and the agent can be removed while required evidence survives. Stop if the endpoint still checks in or residual access remains.

Nizlo early-access example: review the Nizlo early-access beta, then require all five acceptance gates on the first authorized, noncritical Windows device before adding another endpoint.
Small-business first endpoint: use the RMM for small-business IT guide to choose one representative, noncritical Windows device, then require all five acceptance gates before expanding monitoring, patching, scripts, or remote support.
Decision rule: do not average away a failed gate. Correct the underlying risk and repeat the same test before adding another endpoint. If the product is still being shortlisted, return to the small-MSP RMM buying guide and compare operating-model fit before expanding the pilot. If enrollment, policy, compliance, and operational response overlap, assign ownership using the UEM vs RMM comparison.
