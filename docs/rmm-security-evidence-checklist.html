Prove isolation and identity

Review tenant boundaries, privileged authentication, roles, sessions, API credentials, agent identity, enrollment, transport, encryption, and secret handling.

Validate privileged actions

Test how scripts, automation, patching, remote access, and file transfer bind the actor, tenant, target, intent, approval, limits, and audit record.

Reconstruct what happened

Require audit events and monitoring that connect a technician or integration to the authorized action, the device result, and the resulting security decision.

Exercise incident response, recovery, data export and deletion, credential revocation, agent removal, residual cleanup, and independent assurance before rollout.

RMM security checklist FAQ

What should the review cover?

Test tenant isolation, privileged identity, agent enrollment, APIs, scripts, patching, remote access, audit evidence, incident response, resilience, data lifecycle, and offboarding.

What evidence should a vendor provide?

Ask for current, checkable evidence: permission and session controls, agent identity behavior, audit examples, incident and recovery procedures, retention terms, export paths, and access revocation.

How should remote access be tested?

In a controlled tenant, verify authorization, customer and device scope, notification, file transfer, termination, and an audit trail that identifies the actor, target, time, and outcome.

When should security be reviewed?

Review before production, after material changes or incidents, at assurance and contract renewals, and on a recurring risk-based schedule. Give every exception an owner, expiry, and retest date.

Primary security context: CISA and partner guidance warns that legitimate RMM software can be abused and recommends least privilege, preserved and correlated logs, monitoring, tested recovery, access review, and clear MSP/customer security responsibilities.
