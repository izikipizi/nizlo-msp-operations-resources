n8n RMM integration for read-only MSP workflows

Connect a self-hosted n8n instance to the Nizlo RMM API without beginning with write access. The public community node retrieves customers, sites, endpoints, and alerts; two inactive example workflows show a bounded starting point for critical-alert triage and offline-Windows reporting.

Review the source Open release v0.1.0 Use the API preflight Review the Nizlo API
Read-only by designNo create, update, delete, command, script, patch, reboot, remote-session, or token-management operation.
Fixed API originThe node sends its credential only to the fixed production Nizlo API origin and does not accept a custom host.
Credential-free examplesExample JSON omits credentials, starts inactive, and requires a user to choose a local n8n credential before running.

AlertsGet manySearch, IDs, status, severity, assignment, and source

List operations support bounded limits or stable pagination to the reported total. The required token permission is devices.view for customers, sites, and endpoints, and alerts.view for alerts.

Install from the public GitHub package

An administrator of a self-hosted n8n instance with community nodes enabled can review the repository and use the current documented installation path until an npm release is available:

cd ~/.n8n/nodes
npm install github:izikipizi/n8n-nodes-nizlo

Restart n8n after installation. Review n8n's current community-node installation guidance and your own change-control requirements before adding any third-party package to production.

They do not contain tokens, send messages, create tickets, run scripts, patch or reboot endpoints, open remote sessions, or mutate Nizlo data.

Safe evaluation sequence

Review the source and release. Confirm the repository, license, manifest entry points, dependencies, and exact version you intend to test.
Use a test workspace and dedicated token. Keep the token's effective scope to the smallest read permission required by the selected workflow.
Import one inactive example. Inspect every node and filter before selecting a credential or running it.
Run manually with a bounded limit. Compare returned totals and object identity with the Nizlo console before enabling any downstream action.
Keep secrets in n8n credentials. Do not place the personal token in workflow fields, source control, logs, screenshots, or exported JSON.
Add failure handling before scheduling. Bound retry time, handle authorization and rate-limit responses, and alert an owner when the workflow cannot complete.
Record acceptance and rollback. Pin the tested version, name the owner, document how to disable the workflow and revoke its token, and set a review date.

n8n RMM integration questions

Can n8n connect to an RMM?

Yes, when the RMM exposes an API. The current Nizlo node provides typed read operations instead of requiring each workflow to assemble raw HTTP requests.

Can this node change endpoints?

No. Version 0.1.0 is intentionally read-only and exposes no device command, script, patch, reboot, remote-access, or write operation.

Is it on npm?

Not yet. The public GitHub package is available for source review and installation by a self-hosted n8n administrator. Do not infer npm publication or n8n verification.
