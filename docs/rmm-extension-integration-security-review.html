Vendor-neutral review · RMM trust boundaries

Treat every RMM extension as a separate security boundary.

Console MFA and role controls are only part of the model. Inventory every extension path, test its effective authority, and prove that secrets, audit evidence, containment, and revocation work before production use.

1. Complete inventory

List browser extensions, plugins, connectors, webhooks, API clients, remote-support add-ons, service accounts, owners, vendors, versions, affected tenants, and business purpose.

2. Effective authority

Test what each component can read, change, execute, impersonate, or reach. Do not infer authority from the main console role; prove the extension's actual boundary.

3. Authentication path

Document whether the path uses a user session, token, shared secret, certificate, OAuth grant, or service account. Test whether it bypasses console MFA, SSO, or role checks.

4. Secret safety

Require unique rotatable credentials, restrict storage and logging, and fail closed when a secret is empty, missing, default, expired, or revoked.

5. Tenant isolation

Prove that a component cannot cross customer or workspace boundaries. Test representative allow and deny cases and retain the results.

6. Attributable audit evidence

Verify that privileged reads and changes record the integration identity, human initiator where applicable, tenant, target, action, result, and timestamp.

7. Monitoring and kill switch

Define who receives suspicious-use alerts and who can disable the component without waiting for the normal owner. Test the kill switch and record recovery.

8. Review and retirement

Set a review date, rotate secrets, remove unused grants, reconcile orphaned components, and prove that retirement ends access and preserves required evidence.

Fast incident question: if the main console account were secured but one extension secret leaked, what could an attacker still do? The answer defines the extension's real blast radius.
Record the decision: use the RMM security evidence register for ownership, evidence, findings, risk, remediation, exception approval, and retest dates.
Relationship disclosure: Nizlo, a Windows-first RMM and IT-management platform, maintains this vendor-neutral checklist. It is not a certification, audit, or claim that every vendor implements these controls.
